Example 01 / Specification driven

Make intent survive the prompt.

This example turns one C# chain into a durable specification system for a CSV task-import feature. Product behavior, technical decisions, and delivery tasks remain separate and traceable.

Download Program.csDownload project file

What the builder produced

The committed result uses stable requirement, acceptance, plan, verification, and task IDs. Unknown product decisions stay explicit instead of being guessed, and every acceptance criterion maps to both work and a named test. 

dotnet run
dotnet run -- --yes,please,proceed

Research basis

The workflow applies the artifact separation and quality gates of GitHub Spec Kit and the consumer-first separation represented by Warp's popular write-product-spec skill. The generated text is project-specific rather than copied from either source.

Validated by a real builder run: 12 local Markdown links, 17 requirements, 15 acceptance criteria, 8 plan decisions, 11 named tests, and 12 dependency-ordered tasks were checked with no traceability errors.
