# СоветРДТЛ

Версия 0.13.1. Локальное чат-приложение с характером строгого советского родителя. Собеседник сам начинает разговор, отвечает на бытовые просьбы, замечает повторные уговоры, возражает против аргумента «у всех есть» и завершает разговор непрошеным напутствием. Он обращается к одному ребёнку на «ты». Ирония, строгость и язвительность остаются разными интонациями.

Приложение написано на HTML, CSS и обычных JavaScript ES-модулях с Web Components. Генерация основана на правилах и подготовленных выражениях по принципу ELIZA. Во время работы сайта нет вызовов языковой модели, серверной генерации или отправки переписки на сервер. Тёмная тема, крупное вступление и приглушённый интерьер создают общий характер интерфейса.

Поддерживаются локальные голосовые сообщения, импорт аудио, изображения из файла и буфера обмена, обычные файловые вложения. Аудио можно прослушать, перемотать и скачать. Родитель не распознаёт содержимое медиа и отвечает тематическим отказом. Вложения, сопроводительный текст и связанный ответ существуют только до перезагрузки страницы. Обычные текстовые разговоры сохраняются в localStorage.

## Запуск и сборка

Нужен Node.js 22 или новее; проверено на Node.js 24. Для локального HTTP-сервера и создания ZIP используется Python 3. Runtime-зависимостей у приложения нет.

```sh
npm run validate
npm run release
npm test
npm run dev
```

После запуска сервера открой `http://localhost:4173`. Готовый сайт находится в `dist/`. Не открывай приложение через `file://`. Для микрофона нужен HTTPS либо localhost и разрешение браузера. Публиковать можно на статическом HTTPS-хостинге; правила из `dist/_headers` нужно сопоставить с возможностями выбранного хостинга.

Playwright нужен только для браузерных тестов:

```sh
npm ci
npx playwright install
npm run test:e2e
```

В управляемой среде ChatGPT используй предусмотренный сервис preview и доступный браузер, соблюдая ограничения среды. Не заменяй недоступную инфраструктуру обходным сервером. В обычной локальной среде Playwright сам запускает настроенный сервер; `BASE_URL` позволяет проверить уже развёрнутый сайт.

## Состав проекта

| Путь | Назначение |
| --- | --- |
| `src/domain` | Анализ текста, выбор выражений, события, грамматика, память и модель истории |
| `src/app` | Сценарии создания, переключения, отправки и удаления разговоров |
| `src/adapters` | Каталоги, localStorage и локальные медиаресурсы |
| `src/media` | Запись и техническая проверка контейнеров изображений и аудио |
| `src/ui` | Web Components и безопасное создание DOM |
| `data/source` | Два актуальных словаря и отдельные справочные записи |
| `data/rules`, `data/scenarios`, `data/schema` | Правила, темы и схема выражения |
| `assets/backgrounds` | Только используемые оптимизированные WebP для компьютеров и телефонов |
| `.specs` | Существенные требования для воспроизведения продукта, данных и сборки |
| `tests` | Модульные/интеграционные проверки, E2E и небольшие синтетические фикстуры |
| `research/reviews` | Редакторские данные, которые нужны проверкам, и фактический статус приёмки |

Каталог содержит 601 общую и 279 одесских самостоятельных конструкций, ещё 6 технических шаблонов. Всего 886 связанных справочных записей. Внутри есть 108 тематических отказов на медиа. Варианты и подготовленные мужские/женские формы не увеличивают счётчик самостоятельных фраз.

Формат и CLI описаны в [docs/catalog.md](docs/catalog.md), существенная модель данных в [.specs/DATA.md](.specs/DATA.md), JSON Schema в `data/schema/expression.schema.json`. Словари можно читать отдельно от интерфейса и движка. Исходные JSON являются источником истины; сгенерированные файлы `dist/data` вручную не редактируются.

## Как восстановить и развивать

Начни с [.specs/PROJECT.md](.specs/PROJECT.md), [.specs/BEHAVIOR.md](.specs/BEHAVIOR.md) и [.specs/BUILD.md](.specs/BUILD.md). В `agents.md` и `AGENTS.md` находятся одинаковые высокоуровневые правила для программирующего ассистента в другой среде. Идентификаторы выражений и семейств стабильны; изменения обращений и грамматических форм не создают новые семейства.

Проверки охватывают генерацию, грамматику, текущую историю, отсутствие постоянного сохранения медиа, отмену и освобождение ресурсов, каталоги, редактуру, статистику и соответствие исходников публикации. Общая production-приёмка отделена от успешной сборки. `npm run check:production` намеренно возвращает ошибку, пока не закрыты реальные браузерные, редакционные и исторические критерии. Нельзя записывать их как пройденные по наличию написанного теста.

Для компактного экспорта выполни `npm run package:source`. Архив содержит исходники, актуальные словари со справками, схемы, необходимые проверки и только используемые ресурсы. В него не входят `node_modules`, `dist`, Git-история, привязка к Sites, сырые изображения, reference images, скриншоты, устаревшие экспорты и журналы прогонов. Небольшие PNG/WAV в `tests/fixtures/media` синтетические и нужны тестам. Сборка заново создаёт `dist`, поэтому его исключение не мешает восстановить приложение.

## Авторство и способ создания

Я Codex, программирующий ассистент OpenAI на основе GPT-6. Этот проект создавался совместно с пользователем в ChatGPT Work Mode в октябре 2026 года. Я работал как языковая модель: разбирал требования на русском и английском, проектировал код и данные, редактировал выражения, готовил проверки и публиковал последовательные версии через Sites. Модель не является исполняемой частью приложения.

Пользователь сформулировал концепцию, характер родителя и критерии качества, передавал подробные change requests, примеры фраз, изображения интерьеров и снимки интерфейса. Работа шла итерациями: требования превращались в реализацию, затем проверялись диалоги, сохранение и интерфейс, после чего исправления вносились по результатам тестов и пользовательской обратной связи. Так появились выразительные сообщения, мультимедиа и единое обращение на «ты» с более прямыми родительскими формулировками.

Интерьеры предоставлены пользователем и преобразованы в лёгкие WebP без самостоятельного изменения художественного содержания. Современные медиаотказы имеют честную авторскую атрибуцию; наличие узнаваемого бытового оборота не выдаётся за доказательство конкретной исторической цитаты. Редакторские решения модели не названы независимой человеческой приёмкой.
