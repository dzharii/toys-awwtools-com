# Architecture

The popup and on-page catalog consume the same generated descriptor list. They own only presentation, preferences, and selection. The Manifest V3 service worker owns active-tab permission coordination and injection. Animations live in an isolated content-script world, independently of worker suspension. No state essential to a running effect is held in service-worker globals.

The background accepts only fixed command names and IDs present in generated metadata. A popup launch injects `content.js` idempotently, then asks the content runtime to select an ID. The runtime requests its one packaged effect file from the background. The entry registers through the versioned `__angerReliefToyV1` bridge, which exists only in the extension's isolated world. The runtime confirms registration before creating an instance. A monotonically increasing activation epoch invalidates late asynchronous loading or start completion after cancellation. Nothing is exposed through page DOM messages or web-accessible executable resources.

Each effect has `effect.json`, `index.ts`, `contract.test.ts`, attribution, and an acceptance record in its own directory. The build discovers these folders, validates identities/contracts/provenance and required files, emits registry metadata, and creates a separate IIFE per effect. Core execution contains no switch over effect IDs. Generic SDK rendering helpers are bundled into individual entries; this small duplication avoids a global mutable rendering engine and keeps replacement/removal independent. Bundle sizes are recorded in `evidence/bundle-sizes.json`.

The runtime sequence is loading, ready, targeting when needed, starting, active, then stopping/disposal. SDK consumers receive a Document, AbortSignal, Resources, a managed overlay, and finish callback. Modules expose create/start/stop/dispose only. Pause/resume is deliberately absent because this first collection consists of bounded interactions. A single primary instance is allowed. Modules may remain cached without retaining live instances or resources.

Resources owns nodes, animation handles, event handlers, frame requests, timeouts, and property-specific style restoration. Disposal is reversed, idempotent, and exception-contained. The runtime always disposes the shared scope even if an effect's own stop method fails. Finished animations with forwards fill remain owned until disposal so that invisible fragments cannot reappear. No idle effect observers, recurring timers, or animation frames survive Stop. A lightweight extension-message listener and cached immutable module code remain until navigation.

Effects render in one shadow-root overlay isolated from ordinary host CSS. Selection uses a transparent input shield, current viewport hit testing, protected-surface rejection, and a separate outline. Closed shadow roots, embedded documents, and sensitive inputs are boundaries. Keyboard cycling and automatic document selection use a 3000-node bounded traversal. It never scans the whole document every animation frame.

The snapshot helper draws at most 500 visited nodes and 240 words using Range geometry, without cloning HTML or requesting resources. Its flat backgrounds/text are intentionally approximate. Element effects hide only the original element's visibility while their representation is active. Resource cleanup restores only that property if it still has the owned value and priority. No backend, page storage, event synthesis, or persistent page mutation is used.

Local diagnostics contain only allowlisted lifecycle event names, catalog effect IDs/versions, timing numbers, runtime version, and local counters. Reports are limited to the last 100 events and can be viewed or cleared. No arbitrary exception text, page identifiers, selectors, URLs, or contents are accepted. A local activation correlation counter groups loading, starting, targeting and stopping events for each selection. It contains no page data or cross-tab tracking identity.

The original baseline specifications are retained unchanged. `suggestions002-01-foundation-increment.md` records initial scope and supported boundaries. A side panel, regions, drag interactions, autonomous games, and coordinated multi-effect composition remain future extensions, not visible placeholder controls.
