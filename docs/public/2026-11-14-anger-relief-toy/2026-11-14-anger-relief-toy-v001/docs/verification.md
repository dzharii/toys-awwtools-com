# Verification and release gates

`bun run test` rebuilds and runs contract, parameter, resource, effect behavior, and packaged-runtime component tests. Canvas and Web Animations are instrumented in Happy DOM. These checks observe resource ownership, bounded node creation, generated registration, lazy-loading cancellation, intentional failure containment, targeting, search/favorites/wheel flows, target removal, scroll/navigation cleanup, and host-style ownership. Canvas drawing calls and animation keyframes are assertions, not rendered browser pixels.

An initial test expected a byte-identical style attribute; CSSOM correctly normalized spacing. The assertion now compares canonical `style.cssText`, preserving the actual declaration contract. No failed behavior was disabled to pass tests. A production review found that the catalog's own scroll could trigger effect cleanup; scroll termination now applies only in targeting/starting/active states. Additional unit tests exercise this boundary and keyboard selection.

The actual Chromium 156.0.8078.79 startup attempt through installed Playwright 1.62.1 failed at process_singleton_posix.cc: socket() failed: Operation not permitted. A shared desktop browser attempt separately rejected local-file access under browser URL policy. Neither restriction was bypassed. Browser verification remains blocked. No branded Chrome or Edge smoke test was performed.

The reproducible `tests/browser.ts` uses a persistent Chromium context, the unchanged production extension package, the real browser command that grants activeTab, and a localhost synthetic fixture. It does not add test-only host permissions. It captures the catalog/wheel, before/active/after states, exercises every tool three times including reduced motion, checks restoration against the baseline screenshot, guards a form submission target, checks refresh, and fails on page errors. If native shortcut dispatch is unavailable in a particular test environment, perform the equivalent toolbar gesture in a headed run; do not silently loosen production permissions.

Before accepting a release, execute the suite on a compatible environment, inspect each screenshot and the animation itself, and investigate any timing or pixel differences. Ask: is the effect aligned with its target; is its motion recognizably different; is unrelated content intact; does cleanup match the baseline; are keyboard controls and reduced motion usable; do no real actions occur? Deterministic seeds and paused WAAPI keyframes help comparison. Gravity's requestAnimationFrame simulation still needs a controlled-clock visual baseline before pixel-level active-frame regression claims.

Measure startup after module load, frame time on large fixtures, cleanup duration, listener/observer counts, and heap stability after repeated activations. Current static limits are twelve gravity bodies, ten fracture canvases, eighteen impact sparks, sixty-five text fragments, 1200x800 snapshot dimensions, and one active instance for at most ten seconds. At the extreme shatter cap, ten full-size canvases can occupy about 42.24 MB of pixel buffers including the retained source canvas; profile this maximum before approval. Rendering uses CSS-pixel resolution, which deliberately bounds memory but is softer on high-DPI screens.

Support policy: Chrome and Edge desktop version 120+ are targeted APIs, not a claim that every release has been tested. Verify startup, popup, permission grant, isolated injection, selection, cleanup, preferences, worker restart, and restricted-page errors in supported branded stable builds before release. Validate responsive sizes, nested scrolling, zoom, fixed/transformed content, open/closed shadow boundaries, hidden tabs, and hostile CSS.

All eight features remain review-pending. Per-feature acceptance records include every Y question and explicitly identify missing browser, performance, source-audit, and independent-review evidence. Reviewers should return the package for additional work if those gates do not pass. Packaging an installable development ZIP is not acceptance.
