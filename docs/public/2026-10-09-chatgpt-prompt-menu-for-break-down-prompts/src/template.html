Why this menu exists / design notes

The original problem

A request for a detailed heap implementation produced excessive elementary explanation, repeated facts already supplied by the user, unsolicited manual exercises, and artificial recaps. Its diagrams used inconsistent highlighting and sometimes concealed the repeated comparisons in the actual algorithm.

The user wanted control over verbosity, technical depth, assumed knowledge, and teaching style independently. They asked for a visual menu with pictograms and sensible defaults. The restaurant analogy describes choosing options; food and cooking labels do not belong in the generated technical prompt.

The design decision

Preserve intellectual complexity, explain its causes clearly, and spend words where the reasoning is difficult. Already chosen fields and API functions are input context. Worked examples are demonstrations; they do not test the user.

What was reconstructed

This standalone implementation follows seven supplied screenshots and the visible conversation. Their layout and drawings are guidance, not a reason to retain defects: the Why-first connectors and Trace-first arrows have been polished. No complete original HTML, CSS, or JavaScript source was supplied, so the remaining code and styles are reconstructed. This is an independent tool, not an OpenAI product or an official design framework.

Research references

OpenAI UI guidelines inform the restrained typography, outlined iconography, spacing, and accessibility. OpenAI prompt engineering guidance informs the explicit task, instructions, and context boundaries. Both were consulted on October 10, 2026.
