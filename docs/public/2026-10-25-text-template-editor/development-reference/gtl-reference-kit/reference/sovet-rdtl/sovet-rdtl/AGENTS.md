# СоветРДТЛ: правила работы над проектом

Это статическое приложение на HTML/CSS/JavaScript ES-модулях и Web Components. Домен независим от DOM, браузерного хранилища и медиабайтов. Начни с `.specs/PROJECT.md`, `.specs/DATA.md`, `.specs/BEHAVIOR.md` и `.specs/BUILD.md`. README описывает команды и устройство исходного пакета.

Сохраняй серьёзный тёмный интерфейс, заметное вступление, читаемость, видимые роли и понятные кнопки. Не объясняй пользователю шутку и не добавляй технические бейджи. Родитель говорит одному ребёнку на «ты», прямо и уверенно, без почтительных просьб. Ирония и одесский ритм допустимы; поддержка при страхе не должна случайно становиться язвительностью.

Источник истины: `data/source`, `data/rules`, `data/scenarios`. Не редактируй `dist` вручную и не восстанавливай текущий корпус из старых импортов. ID, familyId, происхождение, интонация и сценарии должны оставаться согласованными. Сначала используй CLI-поиск с ограниченной выдачей, затем читай нужные записи. Варианты и формы не считаются новыми самостоятельными фразами.

Грамматические формы готовятся целиком, имена склоняются только по проверенным картам. Не изменяй произвольные окончания и не исправляй обращения повторным анализом текста в UI. Происхождение не выдумывай. Статусы documented/adapted/original/unverified и источники сохраняй честно. Ссылки на .ru и ru.* запрещены в распространяемых данных и UI, кроме Wikipedia. Исторические свидетельства не переписывай так, будто новая адаптация была точной цитатой.

Обычная история использует только актуальную schemaVersion 2. Некорректные единицы пропускаются, миграции не нужны. Медиа, подпись и ответ составляют одну временную пару, исключаемую адаптером до JSON. Blob, URL и имя файла не передаются движку даже через history. Не добавляй серверный upload, распознавание или постоянное медиахранилище. Освобождай URL, потоки и AudioContext; отменённая асинхронная операция не может восстановить удалённый ресурс.

RNG, часы, ID и задержки внедряются для воспроизводимости. Непосредственная опасность проверяется до RNG и возвращает только «(молчит)». Изображения и аудио требуют технической проверки и ограничений памяти, обычные файлы содержательно не читаются. Пользовательские строки вставляются текстовыми DOM-узлами, без innerHTML.

Перед сдачей: validate, release, Node-тесты и относящиеся к изменению браузерные сценарии. После изменения генерации пересмотри затронутые реальные диалоги. Не выдавай модульную проверку или написанный E2E за фактическую браузерную/мобильную приёмку. Проверка production не ослабляется ради зелёного статуса. В управляемой среде используй разрешённую инфраструктуру; на обычном компьютере соблюдай README.

В новой среде не создавай и не публикуй Site автоматически по чужому идентификатору. Пакет переносим и собирает `dist` без аккаунта OpenAI. Публикуй только в явно выбранное пользователем назначение, сохраняя его текущий доступ. В исходном рабочем репозитории контекст хостинга может храниться отдельно; в компактный экспорт он не входит.

Спецификации имеют неизменяемые буквенные коды разделов и ревизии: новый раздел начинается с 00, изменённый получает следующую ревизию, остальные не перенумеровываются. Это правило относится к спецификациям, не ко всем документам. Возвращай полный обновлённый результат работы, не обрывки кода.
