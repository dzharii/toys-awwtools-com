# Illustration production records

The inventory is dist/catalog.json, not the currently visible filtered rows. All 74 entries have separate generated assets mapped by frontend problem ID in dist/illustrations.json. Final files live in dist/assets/illustrations/ and are 960x160 RGBA PNGs with transparent surrounding space. Original user attachments are retained unmodified as references/character-poses.png, algorithm-scenes.png, character-accessories.png and duo-vignettes.png.

Each entry was processed in inventory order: read its task, choose a specific premise scene, generate with the four references, inspect/correct its semantics and character consistency, optimize while preserving alpha, inspect a light/dark composite and integrate. The checklist records stages individually, with final file bytes, SHA-256 and correctness review. Incorrect intermediate generations were revised before acceptance. Images explain situations and statement-defined operations without presenting solution algorithms.

prompts/ records generation briefs and reference names. The first two records are reconstructed scene descriptions, explicitly labeled because their exact initial tool prompts were not retained; all later records retain the generation brief. Corrections are summarized in checklist review notes where needed. High-resolution rejected variants are not included in the delivery. The optimized final artwork and original reference sheets are included.

Run python scripts/validate-illustrations.py to verify every mapping, unique image hash, expected dimensions, actual transparent/opaque pixels, four retained references and completed review flags. Run node scripts/build-offline.mjs after modifying the manifest. The proof composite generated by finish-illustration.py is temporary QA output, not a shipped asset.
